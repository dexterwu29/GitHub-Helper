# TODO：增量翻译优化（备选 / 可优化点）

> 暂不实现，待实际业务场景和开发需求明确后再讨论。

---

## 背景

当前翻译流程为**整篇重翻**：

- 每次任务拉取源文件**完整内容**
- 将**整篇**内容发送给翻译 API
- 用**整篇**翻译结果覆盖 `_i18n/` 下的目标文件

当母文档（如 `1.md`）仅在尾部追加内容时，仍会整篇重翻，导致：

- 浪费 AI token
- 增加翻译耗时

---

## 目标

实现**增量翻译**：仅翻译变更部分，并将结果合并到已有目标文件中。

---

## 难点

1. **变更检测**：需要对比「旧版本」与「当前版本」，需依赖 Git 历史或本地缓存
2. **位置映射**：新增内容需在目标文件中找到正确插入位置，Markdown 结构变化会增加难度
3. **上下文**：单独翻译片段可能缺少上下文，影响术语、语气一致性
4. **非尾部修改**：中间插入、删除、改标题等场景，合并逻辑更复杂

---

## 可行方案（按难度）

| 方案 | 思路 | 难度 |
|------|------|------|
| **A. 尾部追加优化** | 检测 append-only 变更，只翻译新增部分并追加到目标文件 | 中 |
| **B. 分块 + 缓存** | 按 `##` 等拆块，对每块 hash，只翻译 hash 变化的块，再拼回 | 高 |
| **C. LLM 辅助合并** | 将旧源、新源、旧译文一并给 LLM，让其只翻译变更并合并 | 中高 |
| **D. Git diff** | 用 `git diff` 获取变更片段，只翻译这些片段再合并 | 高（位置映射难） |

---

## 建议

- 若业务多为**尾部追加**：优先考虑方案 A
- 若变更位置不固定：方案 B 更通用，但实现成本更高
